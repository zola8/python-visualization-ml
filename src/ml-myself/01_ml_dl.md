Traditional programming:

- inputs + rules = outputs (makes)

ML algorithm:

- inputs + output ==> rules (figures out)

- Why should we use ML?
    - good reason: Why not?
    - better reason: for a complex problem, can you think of all the rules?
    - if you can build a simple rule-based system, do that! Don't use ML.


- Why should we use DL?
    - Problems with a long list of rules (when the traditional approach fails)
    - Continually changing environments (DL can adapt learn to new scenarios)
    - Large collection of data (can you make rules for 1000s or millions of something?)


- When not to use DL?
    - data is uninterpretable by a human
    - when traditional approach is better
    - when errors are unacceptable (the outputs are not always predictable)
    - when you don't have too much data 

ML:
    - structured data (excel table, rows and columns)

DL:
    - unstructured data (image, audio)
